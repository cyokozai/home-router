# ADR 0001: ハニーポットをどこに置くか

## 状態

提案（2026-11-27）。決めるのはオーナーの Yusuke。この文書の「判断（案）」は Claude の案で、Yusuke の決定ではない。

## 背景

2026-11-27 に Yusuke から、ハニーポットをルータ（PC02、VyOS）の中に仕込むのはどうか、という問いが出た。候補は [T-Pot](https://github.com/telekom-security/tpotce) と [endlessh](https://github.com/skeeto/endlessh)。

前提になる環境は次のとおり。

-	PC02 は HP ProDesk 400 G7 SFF（Core i5-10500、6 コア 12 スレッド、メモリ 8GB、SSD 223.6GB）で、VyOS rolling を動かしている。家じゅうの通信が通る本番ルータである。
-	回線は enひかりクロス・v6プラスで、IPv4 は MAP-E。外向きの IPv4 アドレスはほかの契約者と共有し、PC02 が使えるのは自分のポートセット（16 個 × 15 組 = 240 個）だけである。BR は宛先ポートで契約者に振り分けるので、IPv4 の 22 番のようにポートセットに無い番号を叩かれても PC02 には届かない。ポートセットは NAT の口として使っており、受け口に回すと NAT の口が減る。
-	IPv6 は /56 の委任を受けていて、自分のアドレスで任意の番号を受けられる。ただしアドレス空間が広く、無差別の走査は当たりにくい。観測が少ない見込みだが、実測はしていない。
-	CLAUDE.md §1 ルール10: 本番で使う機能は VyOS の `set` だけで設定でき、実機で動くことを確かめる。
-	LAN は VLAN で分けている。Aruba 1930 の右の下の段（6 ポート）を本番用の区画にし、ポートごとに VLAN を決める（2026-11-27 Yusuke 決定）。PVE の versteck（VM を載せる）を本番用の区画に挿す予定である。
-	VyOS には `set container` でコンテナを動かす機能がある。endlessh をこれで動かせるかは試していない。

T-Pot の README で確認したこと（2026-11-27）。

-	メモリとディスクは、Sensor が 8GB・128GB SSD、Hive が 16GB・256GB SSD。TL;DR は「8〜16GB RAM、128GB の空き」。
-	対応 OS は一般の Linux（Debian 13、Ubuntu 26.04、AlmaLinux 10 など）。install.sh は SSH を tcp/64295 に移し、DNS の Stub Listener を止め、firewall の public zone を ACCEPT にし、Docker を入れる。ポートの衝突を避けるため、クリーンなインストールを勧めている。
-	置き方の推奨は TCP/UDP の 1〜64000 を T-Pot へ転送し、64000 より上は信頼できる IP からだけ許すこと。管理の口は 64294・64295・64297。

endlessh の README で確認したこと（2026-11-27）。

-	SSH の tarpit で、終わらないランダムな SSH のバナーをとてもゆっくり送り続ける。本物の SSH は別の口へ移す前提である。
-	単一スレッドの C のプログラムで、poll() を使う。同時接続の上限は既定 4096（`-m`）。メモリの目安の記載は無い。
-	リポジトリに Dockerfile がある。Prometheus の記載は README に無い。

## 検討した案

| 案 | 内容 | 評価 |
|---|---|---|
| A | T-Pot を PC02 に入れる | 不可 |
| B | endlessh を PC02 の VyOS コンテナで動かす | 採らない |
| C | 本番用の区画に、隔離したハニーポット用の VLAN を作り、versteck などの上の VM に置く | 家で置くなら採る |
| D | 自分専用の IPv4 を持つ VPS に T-Pot を置く | 観測そのものが目的なら採る |

**A. T-Pot を PC02 に入れる。** 3 つの理由で不可とする。
1. メモリが足りない。T-Pot は Sensor でも 8GB のメモリを求め、Hive では 16GB を求める。PC02 のメモリは 8GB である。
2. T-Pot は一般の Linux を前提にしていて、install.sh がホストの SSH と firewall の設定を書き換える。対応 OS の一覧に VyOS は無い。
3. `set` だけで組めず、ルール10 に合わない。

**B. endlessh を PC02 の VyOS コンテナで動かす。** `set container` を使えば技術的には `set` だけで組めそうだが、試していない。ただ、外から受ける処理を家じゅうの通信が通る本番ルータに置く危険と、得られる観測の少なさとが釣り合わない。MAP-E では IPv4 の 22 番が PC02 に届かず、IPv6 は無差別の走査が当たりにくい。

**C. 隔離した VLAN の VM に置く。** 本番用の区画に、ハニーポット用の VLAN を作る。versteck などの上の VM をそこに置く。この VLAN からは外にも家の LAN にも自分からは出られないようにする。PC02 は IPv6 の決めた口だけをその VM へ通す。ログは監視の網から取りに行く。

**D. 自分専用の IPv4 を持つ VPS に T-Pot を置く。** 家の網とは完全に切り離す。観測量は多い見込みである。

## 判断（案）

Claude の案として、A と B は採らない。家で置くなら C、攻撃の観測そのもの（登壇のネタなど）が目的なら D とする。

C と D のどちらにするかは、目的（観測量か、家の網の練習か）で Yusuke が決める。

## 理由

-	A はメモリ・OS の前提・ルール10 のどれからも PC02 に合わない。
-	B は本番ルータに外から受ける処理を載せる危険を、観測の少なさで埋め合わせられない。
-	C は受ける処理を PC02 の外に出し、VLAN の隔離で家の LAN から切り離せる。本番用の区画を VLAN で分ける方針は、2026-11-27 に Yusuke が決めている。
-	D は家の網から完全に切り離せる。観測量は多い見込みである。

## 結果として起きること

-	A と B を採らないので、PC02 の `set` で組む設定は増えない。
-	C を選ぶと、ハニーポット用の VLAN と VM が増える。PC02 には、IPv6 の決めた口をその VM へ通す設定が増える。ログは監視の網から取りに行く形になる。
-	D を選ぶと、VPS の契約と運用が増える。家の網には何も増えない。

## 確かめていないこと

-	endlessh の最後の更新日。README からは分からない（表示はコミット 100 件）。
-	T-Pot の最新バージョン。
-	VyOS のコンテナで endlessh が動くか。
-	家の IPv6 に実際にどれだけ走査が来るか。
-	C のための VLAN 番号・アドレス・VM の資源。
-	C で、その VLAN から外にも家の LAN にも出られないことを、VyOS の `set` だけで組めるか。ルール10 の 3 段（`set` で書けるか、commit が通るか、パケットを見て効くか）で確かめる必要がある。
