2026.10.30 — 10G ルータ（PC02）の性能検証の完了
=================================================

PC02（HP ProDesk 400 G7 SFF、Core i5-10500、Intel X710、VyOS 2026.10.16-0024-rolling）を 10G のフレッツ網向けルータとして検証し、主要な性能試験を終えた版。正確な遅延・本来の back-to-back・消費電力などは、下の「残っていること」に回した。検証環境の構築（2026-10-15）から 2026-10-30 までの変更をまとめる。

詳しい結果は [`docs/performance-evaluation.md`](../performance-evaluation.md) にある。

性能の要点
----------

| 項目 | 結果 |
|---|---|
| TCP | IPv4 9.415 Gbps・IPv6 9.285 Gbps（理論値）。双方向 18.7 Gbps |
| MAP-E 越しの TCP | 9.155 Gbps（理論値）。ポートセット 15 組を `set` だけで全部使える |
| フレーム長ごとの転送 | 512B 以上は理論値の 99〜100%（1024B と 1518B が 99.2%）。64B は両向き PDR 5.6 Mpps（送信側の上限に近い） |
| IPv4 と IPv6 | 差なし（78B で 5.66 / 5.65 Mpps） |
| 設定ごとのコスト（64B） | QoS の shaper と RPS は約半分、ステートフル FW は約 24% 減。firewall の set dscp と性能プロファイルはコストが見えない |
| 連続運転 | 本番に近い構成で 3.545 Mpps を 60 分、ロス率 1.9 × 10⁻⁴ |
| バースト | リング 4096 は 0.1 秒（58 万個）までロス 0 |
| 過負荷 | 8〜9 秒で転送が約半分に落ちる。1 秒間隔の観測で、負荷を下げてから 2 秒以内に戻った |
| 再起動 | 転送は約 45 秒止まり、指示から約 49 秒で戻る。設定は残る |
| 接続 | conntrack は既定 26 万件、`set` で 419 万件（約 1GB）。表が埋まった状態で、500 Mbps の確立済みの TCP は落ちなかった |

本番の設定の選び方: DSCP の書き換えは firewall の set dscp で行う（QoS の shaper は使わない）。RPS は入れない。リングは 4096。ステートフル FW には flowtable を添える。どれも `set` だけで書ける。

この版に入ったもの
------------------

### 設定と検査

-	VyOS の設定のファイル化（`vyos/*.cmds`）と、VyOS コンテナでの commit の検査（CI）（#3）
-	containerlab のトポロジーと、設計との静的な整合性検査（#4）、PC02 を通した E2E 検査（疎通・MAP-E・DSCP）（#7）
-	実機の構成（自宅 LAN の管理系・VRF MGMT・実機の型番）に合わせた各機の設定の保存（#8）
-	MAP-E のポートセット 15 組を `set` だけで使う設定（`vyos/mape-portsets.cmds`）（#9）
-	委任プレフィックスから v6プラスの値と `set` の行を計算する道具（`scripts/mape_calc.py`）と、PC02 の SNMP（`vyos/snmp-mgmt.cmds`）（#10）
-	CodeRabbit によるレビュー（`.coderabbit.yaml`）（#11）

### 試験と結果

-	T0〜T8、P1〜P4、L1・L2、N1・N2、E2・E4・E5 の結果と、性能評価のまとめ（#9、#12）
-	E1（残りのフレーム長）・E2 の 3 巡（#13）、R1 再起動にかかる時間（#14）、E3 バーストと E4 の切れ目のない過負荷（#15）の実行器と集計
-	E1・E2・E3・E4・R1 の結果（このリリースの直前の PR）

### 直したもの

-	`scripts/pc02-commit.sh`: community の値によって確認待ちの commit-confirm を見落とし、5 分後に PC02 が自動で再起動するおそれがあったのを直した。鍵の SSH の確認は、接続を使い回さずに必ず新しく認証する（#16）
-	試験の記録で SNMP の community を伏せる。引用符の有無によらず、PC02 の設定を書き出す全部の実行器で伏せる（#16）
-	`scripts/pktgen-keepalive.sh`: 送り先のリンクが落ちても、戻ったら送り直す（R1 で pktgen がリンク断で止まった）（#16）
-	実行器が失敗を成功として返す、途中で止まった回を済みとみなす、などの流れの不具合（#12、#13）
-	機材の情報（`configs/*/inventory.txt`）から、自宅 LAN の実際の IPv6 アドレスと PC02 のシリアル番号・UUID を伏せ字にし、`configs/` と `results/` に実際のグローバル IP・シリアル・秘密の値が入ったら落ちる検査（`tests/test_no_sensitive_data.py`）を足した（#19）

残っていること
--------------

-	正確な遅延（時刻を付けられる試験機が要る）、PC02 の小さなフレームの本当の上限（速い送信機が要る）、消費電力
-	過負荷で転送が半分に落ちる理由
-	実回線（v6プラス）での MAP-E と DSCP の書き換えの確認、DHCPv6-PD、プレフィックスの変化への追従
